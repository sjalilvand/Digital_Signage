# راهنمای نصب و راه‌اندازی

این سند مراحل کامل استقرار سامانه را پوشش می‌دهد: سرور (Docker)، شبکه Wi-Fi ساختمان، جفت‌سازی باکس‌ها و آزمون میدانی.

## ۱. پیش‌نیازهای سرور

- یک کامپیوتر/سرور داخل ساختمان (پیشنهادی) با لینوکس و **Docker Engine + Docker Compose plugin**
- حداقل منابع پیشنهادی برای سه باکس: ۲ هسته CPU، ۴GB RAM، ۵۰GB دیسک آزاد (بسته به حجم محتوا)
- کارت شبکه متصل به همان شبکه Wi-Fi/سوییچی که اکسس‌پوینت آسانسورها به آن وصل است
- اگر سرور بیرونی (اینترنتی) استفاده می‌شود: اینترنت پایدار + IP ثابت/دامنه + TLS (پیشنهاد: nginx با گواهی معتبر در جلو)

> سرور محلی وابستگی به اینترنت را حذف می‌کند و برای سه آسانسور در یک ساختمان گزینه مناسبی است.

## ۲. نصب سرور

```bash
# ۱) دریافت کد
git clone https://github.com/sjalilvand/Digital_Signage.git
cd Digital_Signage

# ۲) تنظیمات محیطی
cp .env.example .env
nano .env    # SECRET_KEY، رمز دیتابیس، رمز کاربر admin و GATEWAY_PORT را حتماً تغییر دهید

# ۳) اجرا
docker compose up -d --build
docker compose ps        # همه سرویس‌ها healthy/up
docker compose logs api  # بدون خطا؛ «superuser» ساخته شده
```

پس از بالا آمدن سرویس‌ها:

| آدرس | توضیح |
|---|---|
| `http://<server-ip>:8080/` | پنل مدیریتی (ورود با DJANGO_SUPERUSER_USERNAME/PASSWORD) |
| `http://<server-ip>:8080/api/v1/` | API پنل |
| `http://<server-ip>:8080/device-api/v1/` | API دستگاه‌ها |

دستورهای مدیریتی پرکاربرد:

```bash
docker compose logs -f worker      # دیدن پردازش محتوا (PDF و …)
docker compose exec api python manage.py createsuperuser
docker compose restart api
docker compose pull && docker compose up -d --build   # ارتقا
```

## ۳. تنظیم شبکه Wi-Fi برای آسانسورها

بدنه فلزی کابین و حرکت آسانسور باعث افت/قطع Wi-Fi می‌شود. طراحی سامانه آفلاین-محور است، اما برای **دانلود** محتوا به پوشش کافی نیاز دارید:

1. روی هر طبقه (یا در مسیر حرکت) پوشش Wi-Fi با اسکن با یک گوشی/لپ‌تاپ بسنجید؛ RSSI بهتر از `-70dBm` در نقاط توقف پیشنهاد می‌شود.
2. ترجیحاً اکسس‌پوینت اختصاصی برای باکس‌ها با SSID و رمز ثابت (بدون captive portal) راه‌اندازی کنید.
3. فایروال/روتر: باکس‌ها فقط باید به سرور روی پورت `8080` دسترسی داشته باشند (محدودسازی خروجی به اینترنت اختیاری است).
4. **آزمون میدانی الزامی است**: پوشش Wi-Fi را در همه طبقات نباید بدون تست فرض کرد؛ ممکن است دانلود فقط در بعضی نقاط مسیر ممکن باشد — معماری دانلود/نمایش محلی برای همین وضعیت طراحی شده است.

## ۴. ساخت دستگاه‌ها و جفت‌سازی باکس‌ها

### در پنل (یک‌بار برای هر باکس)
1. ورود → **دستگاه‌ها** → «افزودن دستگاه» → نام (مثلاً «آسانسور شرقی») را وارد کنید.
2. **کد جفت‌سازی** ۸ کاراکتری نمایش داده می‌شود (اعتبار ۲۴ ساعت، یک‌بارمصرف).

### روی باکس اندروید
1. Wi-Fi باکس را به شبکه ساختمان وصل کنید.
2. اپلیکیشن «نمایشگر آسانسور» (`android/README.md` → ساخت APK و نصب) را باز کنید؛ صفحه «اتصال به سرور» باز می‌شود.
3. آدرس سرور (مثلاً `http://192.168.1.10:8080`) و کد جفت‌سازی را وارد و «اتصال» بزنید.
4. پس از موفقیت، دستگاه در پنل «آنلاین» می‌شود و برنامه فعال (در صورت وجود) خودکار دانلود می‌شود.

> کد جفت‌سازی پس از موفقیت باطل می‌شود. در صورت گم شدن/لو رفتن، از پنل «توکن جدید» بگیرید.

## ۵. حالت کیوسک و اجرای خودکار

اپ پس از نصب: تمام‌صفحه، روشن‌ماندن صفحه، اجرای خودکار پس از بوت (`BootReceiver`) و غیرفعال‌بودن دکمه Back. برای تضمین کامل:

- اگر باکس از **ADB** پشتیبانی می‌کند، برنامه را به‌عنوان Home/لانچر پیش‌فرض تنظیم کنید:
  `adb shell pm enable ...` نه — راه ساده: Settings → Home → انتخاب «نمایشگر آسانسور» در صورت پشتیبانی، یا استفاده از Screen Pinning:
  `adb shell cmd activity pin <task-id>` یا از Settings → Security → Screen pinning.
- ویژگی‌هایی مثل «ذخیره برق/Deep Sleep» را خاموش کنید (Stay awake در Developer options).
- برخی مدل‌ها قابلیت سازنده (Auto-boot / Kiosk mode) دارند — روی مدل واقعی باکس آزمایش شود (SRS §13).
